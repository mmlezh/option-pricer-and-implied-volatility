# Инструкции агенту

Проект на C++20 по программной инженерии в HFT: вычислительная библиотека и консольное приложение для оценки европейских call/put по модели Black–Scholes–Merton с постоянной непрерывной дивидендной доходностью и восстановления implied volatility по цене опциона.

## Назначение и развитие

Целевой функционал: цена опциона; Delta, Gamma, Vega, Theta и Rho; IV методом бисекции и защищённым методом Ньютона; диагностика вычислений; команды CLI `price`, `greeks`, `iv`; пакетная обработка CSV последовательно и фиксированным числом рабочих потоков.

Сейчас реализованы цена call/put, валидация и предельные случаи, демонстрационная программа, тесты, бенчмарки и инфраструктура сборки и документации. Остальные возможности — план развития, а не уже доступный API. Актуальное описание реализованного и планируемого функционала поддерживать в `README.md`.

## Структура и архитектура

- `include/option_pricer` — публичный API и типы результатов.
- `src` — реализация вычислений.
- `app` — сейчас демонстрация; при развитии проекта — консольный интерфейс.
- `tests` — тесты GoogleTest.
- `benchmarks` — измерения Google Benchmark.
- `docs` — документация и результаты проверок.
- `.github/workflows` — CI и публикация Doxygen.

Архитектура — модульная библиотека и один CLI-процесс. Вычислительное ядро не зависит от файлов, CLI, сети, логирования и изменяемого глобального состояния. CSV и пользовательский интерфейс оформлять отдельными адаптерами. Не вводить иерархию виртуальных классов для единственной модели BSM.

Пакетный исполнитель при реализации должен сохранять порядок и идентификаторы записей, включая ошибки. Использовать заранее выделенный массив результатов и непересекающиеся диапазоны для рабочих потоков `std::jthread`; не создавать поток на каждый опцион.

## Сборка и проверки

Команды из корня этого проекта:

```bash
cmake -S . -B build -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Release
make -C build -j2
ctest --test-dir build --output-on-failure
./build/pricing_demo
./build/pricing_bench --benchmark_min_time=0.02s
make -C build docs
```

Поддерживаемое окружение и установку инструментов смотреть в `README.md`. Команды выше относятся к текущим целям сборки; обновлять их при изменении интерфейса проекта.

При изменении кода собрать проект и запустить относящиеся к нему тесты. При изменении документации проверить Doxygen. Проверять цены и греки независимыми эталонами и математическими свойствами; IV — также обратным прайсингом и проверками диагностики. При добавлении параллельной обработки проверять совпадение с последовательной и отсутствие гонок средствами ThreadSanitizer. Сравнения производительности проводить на одинаковых входах и сохранять условия измерений. Локальную проверку не выдавать за успешный GitHub CI или опубликованный сайт.

Зависимости загружаются CMake в build/_deps, версии и SHA-256 закреплены. Не сохранять пути к /tmp, чужим build-каталогам или системным копиям GoogleTest/Benchmark в исходных настройках. При изменении сборки проверять чистую конфигурацию и повторную конфигурацию без сети. Не запускать несколько конфигураций/сборок одновременно в одном build-каталоге. Генерируемые build и compile_commands.json не коммитить.

## Стиль и численный контракт

Стиль: C++20, четыре пробела, snake_case для функций/переменных, PascalCase для типов. Ошибки возвращать через типизированные статусы; текущий API использует `Status`. Комментарии API оформлять для Doxygen, объяснять единицы и ограничения.

Вычисления выполнять в `double` без округления внутри ядра. Цена, S и K выражаются в одних денежных единицах; T — в годах; r, q, sigma и IV — в долях, ставки — с непрерывным начислением. Отрицательные конечные ставки допустимы. Vega и Rho — производные по величинам в долях, Theta — по течению календарного времени, на год.

Отклонять NaN/Inf, неположительные S/K и отрицательные T/sigma; обнаруживать нечисловые промежуточные результаты. Для цены сохранять предельные формулы при T=0 и sigma=0. При реализации греков возвращать отдельный статус для этих неподдерживаемых границ. Для IV проверять границы цены, различать неопределимость при T=0, ограничение поиска, недостаточную численную разрешимость и отсутствие сходимости. Не выдавать последнее приближение за успешный результат. Защищённый Ньютон должен сохранять интервал с корнем и переходить к бисекции при ненадёжном шаге.

## Ограничения работы агента

Реализовывать согласованные задачи поэтапно; наличие возможности в плане не означает поручения реализовать её целиком в текущем изменении. Поддерживать автономную сборку этого репозитория без зависимости от соседних проектов.

В обязательный объём не входят американские и экзотические опционы, торговые подключения, GUI, REST-сервер, СУБД, GPU и ручная SIMD-оптимизация. Не добавлять их без изменения согласованного объёма проекта.

Не менять эталоны ради прохождения тестов. Не добавлять секреты, скачанные исходники зависимостей или результаты сборки в Git. Новые зависимости добавлять только при обоснованной необходимости, закрепляя версии. Не менять remote и не публиковать проект без указанного пользователем назначения и поручения на публикацию.
